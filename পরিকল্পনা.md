# ১. প্রথমে বর্তমান architecture-টা কী অবস্থায় আছে

একই সঙ্গে `POSDashboard.tsx` প্রায় 67KB এবং `pos-store.ts` প্রায় 27KB—এগুলো ভবিষ্যতে maintenance-এর বড় জায়গা হয়ে উঠবে। তাই **feature বাড়ানোর সঙ্গে সঙ্গে modularisation জরুরি**।

# ৩. Multi-tenant অংশ আরও শক্ত করো

তোমার schema-তে `Business` + `Membership` ইতিমধ্যেই আছে।

এটা ভালো foundation।

কিন্তু আমি architecture-টা এমন করতাম:

```text
User
 │
 ├── Membership → Business A
 │
 ├── Membership → Business B
 │
 └── Membership → Business C
```

তারপর:

```text
Business
│
├── Users
├── Products
├── Categories
├── Sales
├── Purchases
├── Customers
├── Suppliers
├── Expenses
├── Settings
├── Reports
└── Devices
```

### খুব গুরুত্বপূর্ণ পরিবর্তন

`businessId` শুধু application-level filter হিসেবে নয়, **প্রতিটি tenant-owned entity-এর security boundary** হওয়া উচিত।

যেমন:

```ts
db.product.findMany({
  where: {
    businessId,
  }
})
```

এটা সব জায়গায় বাধ্যতামূলক।

আরও ভালো:

```ts
const tenant = await requireBusinessContext();

const product = await db.product.findFirst({
  where: {
    id,
    businessId: tenant.business.id
  }
});
```

অর্থাৎ user থেকে আসা:

```json
{
  "businessId": "ABC"
}
```

বিশ্বাস করবে না।

**session → membership → business**

থেকেই tenant নির্ধারণ করবে।

কিন্তু AI-কে প্রথমে core billing calculation-এর মধ্যে ঢোকাবে না।

AI layer হবে:

```text
POS Data
   ↓
Analytics Layer
   ↓
AI Assistant
```

উদাহরণ:

> “এই সপ্তাহে কোন ১০টা পণ্য সবচেয়ে বেশি বিক্রি হয়েছে?”

> “আগামী সপ্তাহে কোন পণ্যের stock শেষ হতে পারে?”

> “কোন customer-এর due বেশি দিন ধরে আছে?”

> “গত মাসের তুলনায় বিক্রি কমেছে কেন?”

> “আজ দোকানের gross profit কত?”

AI উত্তর দেবে **database facts-এর ভিত্তিতে**, নিজের থেকে হিসাব বানাবে না।

# ২৬. Offline system আরও শক্ত করো

এখানে তোমার project-এর একটা বড় শক্তি আছে।

README অনুযায়ী IndexedDB + action queue + idempotency + `/api/sync` architecture ইতিমধ্যেই আছে।

এখন এটাকে এমন করো:

```text
ONLINE
   │
   ├── Server
   └── IndexedDB mirror

OFFLINE
   │
   └── IndexedDB
        │
        └── Action Queue
             │
             ↓
          Retry
             │
          ONLINE
             │
             ↓
           Sync
```

প্রতিটি offline action:

```json
{
  "idempotencyKey": "...",
  "deviceId": "...",
  "businessId": "...",
  "userId": "...",
  "action": "sale:create",
  "createdAt": "...",
  "payload": {}
}
```

# ২৮. Offline conflict system

এটা ভবিষ্যতের সবচেয়ে কঠিন অংশ।

ধরা যাক:

```text
Device A
Stock = 10

Device B
Stock = 10
```

দুই জায়গা থেকে offline sale:

```text
A sells 7
B sells 6
```

বাস্তবে stock ছিল 10।

তাই sync-এ:

```text
A → accepted
B → conflict
```

B-এর জন্য:

```text
Sync conflict

Product: Rice
Requested: 6
Available server stock: 3

[Resolve]
```

এই ধরনের conflict resolution দরকার।
